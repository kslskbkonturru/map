# О проекте

**Service Transformation Map** — это веб-приложение для визуального управления программами изменений.

Основная идея продукта — представить программу не как перечень проектов или набор KPI, а как **карту трансформации**, показывающую путь организации от текущего состояния (**AS IS**) к целевому (**TO BE**).

Продукт создается как универсальная платформа и может использоваться для управления любыми программами развития компании.

---

# Видение продукта

Руководитель программы должен открыть главную страницу и за **10–15 секунд** получить ответы на пять ключевых вопросов:

1. Какова цель программы?
2. Где мы сейчас на пути к этой цели?
3. Из каких фокусных проектов состоит программа?
4. Какие проекты сейчас определяют успех программы?
5. Какие риски, блокировки или внешние зависимости требуют внимания?

Если пользователь получает эти ответы без изучения десятков документов, значит продукт выполняет свою задачу.

---

# Философия продукта

Service Transformation Map **не является**:

- системой управления задачами;
- аналогом Jira;
- аналогом MS Project;
- системой документооборота;
- BI-платформой.

Service Transformation Map — это **пространство управления программой изменений**.

Главная задача продукта — помочь руководителю видеть программу как единую систему.

---

# Основные принципы

## 1. Всё начинается с карты

Главный экран приложения — интерактивная карта программы.

Не таблица.

Не список.

Не набор KPI.

---

## 2. Минимум интерфейса

Каждый элемент страницы отвечает только на один вопрос.

Интерфейс не должен перегружать пользователя.

---

## 3. Данные отделены от интерфейса

Интерфейс ничего не знает о конкретной программе.

Все данные загружаются из JSON.

В дальнейшем источник данных может быть заменен на:

- Excel;
- SharePoint;
- REST API;
- корпоративную БД.

Без изменения интерфейса.

---

## 4. Продукт универсален

Программа "Сервис" является первым примером использования.

Архитектура должна позволять применять продукт для любых программ компании.

---

## 5. Простота важнее функциональности

Мы сознательно не создаем сложную корпоративную систему.

Ценность продукта — в простоте использования.

# Основные сущности

## Программа

Верхний уровень управления.

Содержит:

- цель;
- период;
- прогресс;
- показатели;
- фокусные проекты.

---

## Фокусный проект

Крупное направление изменений.

Пример:

- Уровни сервиса
- Решаем запросы клиентов
- Voice of Customer
- CXI

---

## Проект

Самостоятельная инициатива внутри фокусного проекта.

Каждый проект содержит:

- описание;
- статус;
- владельца;
- сроки;
- прогресс;
- зависимости;
- историю изменений.

---

## Активность

Минимальная единица изменений.

Активности используются для детализации проектов.

## Build 004.04 — Module Contracts

Между основными модулями используется единый контракт вызовов:

- `STM.Layout.build({ focuses, projects, workspace })` — рассчитывает позиции карточек.
- `STM.SVG.render({ links, projects })` — рисует связи между уже отображёнными карточками.
- `STM.Timeline.render({ projects, history })` — строит Timeline по переданному набору проектов.
- `STM.Modal.openProject(projectId)` — открывает проект только по его ID.
- `STM.Renderer` является координатором данных и передаёт данные дочерним модулям; `App` не вызывает `Layout` напрямую.

Для связей каноническими полями данных являются `source` и `target`. `from` / `to` поддерживаются только как обратная совместимость внутри визуального слоя.
